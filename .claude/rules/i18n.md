# Internationalization

## Setup

- next-intl with the locales defined in `src/i18n/routing.ts`
- Every route lives under `src/app/[locale]/`
- Messages live in `src/i18n/messages/<locale>.json`

## Strings

- No hardcoded user-facing text in components. Exceptions are proper names and email addresses
- Every new key goes into every message file with the same structure and order
- Top-level namespaces are PascalCase, one per page or component: `HomePage`, `PrivacyPage`, `PageHeader`, `Footer`
- Nested keys are camelCase and grouped by section: `banner`, `about`, `resume`
- Recurring key names: `title`, `description`, `content`, `list`, `name`, `address`. Strings shared within a namespace go into `misc`
- Inside a group, plain string keys come first. Separate nested groups with a blank line

## Translating in code

- Async server code (`generateMetadata`, async pages): `const t = await getTranslations({ locale, namespace: "HomePage" });` from `next-intl/server`, with `locale` from the awaited `params`
- Client components and non-async components: `useTranslations("Namespace")` and `useLocale()` from `next-intl`
- Build keys from data with template literals: `` t(`resume.${item.key}.title`) ``, `` t(`rights.list.${right}`) ``
- Link tags in messages are named `link` or `link-<name>`: `link-github`, `link-linkedin`

## Dates

Format dates with the current locale:

- Month and year: `toLocaleString(locale, { month: "long", year: "numeric" })`
- Full date: `toLocaleDateString(locale, { day: "numeric", month: "long", year: "numeric" })`

## Tone

- English headings use Title Case: "Collected Log Data", "Rights of the Data Subject"
- German addresses the reader informally ("Kontaktiere mich") and formally with "Sie" in legal text like a privacy policy
